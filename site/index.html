The big idea

Your devices are islands. They don't have to be.

Your laptop has the keyboard. Your desktop has the GPU. The home server has the disks, and the Mac in the kitchen has the speakers. Each one runs its own scripts, and none of them can borrow what the others are good at. Wiring them together means custom endpoints, hard-coded addresses, and hoping the right machine is awake.

bricolo gives every device the same small node and the same standard library. Your automations call that library and never ask where the work happens. One line of configuration decides, and the router falls back when a machine is gone.

It started as a port of a Hammerspoon setup that had outgrown one Mac.

How it works

How a call finds the right machine

  1. 1

    Every device runs a node

    Each node offers the same 24 capabilities, defined once in WIT and implemented natively per OS: Accessibility and CGEvent on macOS, X11, Hyprland and D-Bus on Linux, Win32 and WinRT on Windows.

  2. 2

    You pair the ones you trust

    bricolo peer add desktop <id> --allow speech. Each device lists exactly what the other may call, and refuses any key it doesn't know. Calls travel encrypted over iroh QUIC or Tailscale.

  3. 3

    One line picks where a call runs

    speech = ["desktop", "local"] sends speech to the desktop and falls back to this machine when the desktop is asleep.

Build

Three ways to make an app

Script

Lua 5.4 · trusted · instant

Drop a .lua file in scripts/ and it runs. Save it and it reloads. The fastest way to glue things together.

bricolo new-script clip --template hotkey-tool

Plugin

Rust → WebAssembly · sandboxed · portable

One .wasm runs on every OS. It declares the capabilities it needs, you approve them once, and it can't touch anything else.

bricolo new tiler --template hotkey-tool

Sidecar

Python, Node.js or Rust · any model

A local HTTP server for the work a node can't do itself, like a speech model or OCR. The node starts it, checks it, and restarts it.

bricolo new-sidecar ocr --template python

Or describe it, and let your agent build it

One command teaches Claude Code, Codex, Gemini CLI, OpenCode or Cursor how to build apps for your node. Ask for "OCR a part of the screen I select on ctrl+alt+shift+o and copy the text", and the agent plans it, writes it, installs it and checks that it runs. The permission model limits what a generated plugin can touch.

bricolo skill install --agent all

The hub

Every app, sidecar and peer in one window

The hub shows what needs attention, your widgets, every app with its switch and shortcuts, your sidecars, your peers and their routes, and live logs. It runs in its own process, so closing it never stops an automation.

Scripts and plugins can also show floating panels: captions while you dictate, toasts, choice lists and review windows.

Encrypted, device to device

Nodes pair by public key and talk over QUIC. When no direct path exists, a relay forwards packets it can't read.

Hot reload everywhere

Save a script or rebuild a plugin, and only that app restarts. The rest of the node keeps running.

Installs pinned by hash

Share apps as GitHub releases. plugins.lock records every sha256, and bricolo update shows new permissions before granting them.

Starts at login

A signed macOS app, and bricolo service to start at login through launchd, systemd or Task Scheduler.

What's next

Where this can go

The design already leaves room for each of these. They're directions, not promises, and issues about them are welcome.

Remote media

The mesh already carries media streams. Next: the phone on your desk becomes the microphone or camera for the desktop.

Automatic routing

Let the router pick by latency, battery, load or GPU, and show its reasoning in the hub.

Phones and small devices

iOS and Android nodes for camera, mic and location. A Raspberry Pi as an always-on node for sensors and the home.

Apps built on apps

Plugins that import other plugins, so "meeting notes" builds on "dictation" and "summarize" without copying them.

An app store for friends

Peers already serve the plugins they run. Add signatures and a small catalog, and you can share apps with people you trust.

A computer for AI agents

In progress: bricolo mcp serves the library to agents over MCP, so an agent can hear you on the laptop, think on the GPU box and speak in the kitchen, inside the same permissions.

Try it in four commands

git clone https://github.com/Pierre-Mike/bricolo.git && cd bricolo
cargo install --path crates/node
bricolo run &
bricolo new-script clip --template hotkey-tool

Press ctrl+alt+cmd+c and the clipboard shows up in a notification. Open the script, change it, save, and it reloads.
